# reference/

## Purpose
The investigation's public-facing glossary — plain-language answers to the "boring but load-bearing" technical questions (What is an IDB? What is a PILOT?), so articles can link a term instead of re-explaining it.

## Contents
One markdown file per entry, dash-named after the question or term. Rigid template:
- `# Term` as the title
- 150–300 words of plain-language explanation, written for a cold reader
- **Why it matters in this investigation** — one factual sentence
- **Sources** — statutes, filings, or project files

Categories (become the site sidebar later): Mechanisms · Institutions · Comparisons.

## Source Type
**Output Artifact** — publishable explainer content, drafted from primary sources elsewhere in the project. Not itself a source; every claim traces to the cited material.

## Handling Instructions
- **Encyclopedia voice only.** Neutral, sourced, no case-making. If an entry starts arguing, the argument belongs in an article — cut it. The credibility of this section depends on it reading like a civics resource.
- Write for the cold reader: no unexplained jargon; an entry may link other entries.
- Destined to render as the `reference/` section of the combined site (same markdown-source → static-HTML pattern as the tracker). Keep the template rigid so rendering stays mechanical.
- Update entries when primary documents change the facts; note the date in the entry when a material revision happens.
